# Architecture & Mermaid Diagram Standards

1. **Supported Mermaid Types ONLY**:
   - Architecture / Data Flow: `flowchart TD` or `flowchart LR`
   - End-to-End Request / Auth Flows: `sequenceDiagram`
   - Database Schema: `erDiagram` (rely primarily on the deterministic ERD generated by `SchemaParser`)
   - Lifecycle / Status Transitions: `stateDiagram-v2`
2. **Strict Syntax Safety**:
   - Quote every node label containing spaces, Arabic characters, parentheses, slashes, or brackets:
     `API["API Gateway (Yii2 REST)"]` instead of `API[API Gateway (Yii2 REST)]`.
   - Use simple ASCII alphanumeric + underscore node IDs (`WebApp`, `AuthCtrl`, `MySQL_DB`).
   - Avoid HTML tags (`<br/>`, `<b>`) inside node labels so every Markdown viewer renders cleanly.
   - Limit each flowchart or sequence diagram to **6–14 nodes/actors** so diagrams remain readable. Split large systems into modular sub-diagrams rather than one giant graph.
3. **Code-Grounded Nodes**: Every actor, controller, service, queue, or database node in a diagram must map directly to real files or dependencies verified in the repository.
